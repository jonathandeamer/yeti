# yeti — Contributing Guidelines Design Spec

Create a simple and lighthearted `CONTRIBUTING.md` file at the root of the repository to guide new contributors.

## Goal
Establish a clear contributing workflow that details the 10 KiB source budget limit, Conventional Commit requirements, AI-assisted code safety, and feature suggestion processes.

## Approach
Create `CONTRIBUTING.md` with:
- **Rule 1: Pack Light (10 KiB Budget)**: Capping `src/yeti.c` at 10,240 bytes.
- **Rule 2: Sign the Logbook (Conventional Commits)**: Formatting messages correctly and utilizing `make init-hooks`.
- **Rule 3: Original Snow Only (Fresh Code & AI)**: Guidelines for writing independent code and testing AI outputs without copying external skiing codebases.
- **Rule 4: Upgrades & Obstacles (Feature Ideas)**: Suggesting features via issues.

No other code files or configurations will be changed.
